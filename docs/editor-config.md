# Налаштування редактора та .gitignore

Команда працює на різних системах і в різних редакторах. Без спільних правил у файлах з'являються зайві зміни: змішані кінці рядків, різні відступи, пробіли в кінці рядків. Файл `.editorconfig` задає ці правила один раз для всіх, а `.gitignore` не пускає в репозиторій зайве.

## 1. .editorconfig

Файл лежить у корені репозиторію. Редактор читає його автоматично: у VS Code потрібне розширення **EditorConfig for VS Code**, у редакторах JetBrains підтримка вбудована. Щоб перевірити, що правила діють, подивіться на рядок стану VS Code: там має бути `LF` і `UTF-8`.

Розбір по рядках:

- `root = true`: це головний файл, шукати правила вище по теках не треба. Без цього редактор міг би підхопити чужий `.editorconfig` із батьківської теки.
- `[*]`: далі йдуть правила для всіх файлів.
- `charset = utf-8`: кодування UTF-8. Без нього кирилиця в документах може перетворитися на нечитабельні символи.
- `end_of_line = lf`: кінець рядка в стилі Linux. Скрипти й Dockerfile із CRLF можуть не запускатися на Linux-серверах, а в Git з'являються зайві різниці.
- `insert_final_newline = true`: порожній рядок у кінці файлу. Так заведено в Unix, і Git не показує попередження «No newline at end of file».
- `trim_trailing_whitespace = true`: прибирає зайві пробіли в кінці рядків, щоб вони не потрапляли в історію змін.
- `indent_style = space` і `indent_size = 2`: відступи двома пробілами. Однаково виглядають у будь-якому редакторі й добре підходять для YAML і JSON.
- `[*.md]` і `trim_trailing_whitespace = false`: для Markdown правило вимкнено, бо два пробіли в кінці рядка означають перенос рядка.
- `[Makefile]` і `indent_style = tab`: у Makefile відступ має бути табуляцією, з пробілами файл не працює.

## 2. .gitignore

`.gitignore` містить шаблони файлів, які Git не відстежує. Правила запису: `#` починає коментар, `*` означає будь-які символи, `/` наприкінці означає теку.

Наш файл поділено на три групи:

- **Операційна система й редактори** (`.DS_Store`, `Thumbs.db`, `Desktop.ini`, `.vscode/`, `.idea/`): службові файли системи та особисті налаштування редакторів. Вони різні в кожного й нікому не потрібні.
- **Секрети** (`.env`, `*.pem`, `id_rsa*`, `id_ed25519*`): паролі, сертифікати й приватні SSH-ключі. Секрет, який потрапив у коміт, лишається в історії навіть після видалення файлу, тому краще не допустити цього заздалегідь.
- **Залежності й артефакти збірки** (`node_modules/`, `__pycache__/`, `*.pyc`, `.venv/`, `dist/`, `build/`): усе, що відновлюється командою й займає багато місця.

Важливе обмеження: `.gitignore` діє лише на файли, які Git ще не відстежує. Якщо файл уже закомічено, його треба прибрати з індексу, залишивши на диску:

````
git rm --cached шлях/до/файлу
````

## 3. Як це пов'язано з налаштуваннями Git

`.editorconfig` керує тим, як редактор записує файл. Параметр Git `core.autocrlf` керує перетворенням кінців рядків при отриманні файлів із репозиторію та при коміті. Разом вони дають однакові кінці рядків у репозиторії незалежно від того, хто на якій системі працює. Для файлів, дуже чутливих до кінців рядків (скрипти хуків), використовується ще й `.gitattributes`: він з'являється в репозиторії разом із хуком `commit-msg`.
