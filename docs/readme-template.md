## Що писати в кожному розділі

**Назва й опис.** Два речення про мету проєкту без технологічного жаргону: «Довідник команди з Git», а не «Markdown-репозиторій на GitHub». Читач має зрозуміти, чи це те, що йому потрібно.

**Можливості.** Короткий список того, що проєкт уміє. Три-п'ять пунктів, кожен починається з дієслова чи іменника-дії.

**Вимоги.** Програми й мінімальні версії: «Node.js 20 або новіша», а не просто «Node». Без версій фраза «в мене працює» нічого не гарантує.

**Встановлення.** Команди, які можна скопіювати й виконати по черзі на чистій машині. Перевіряйте самі: найчастіше випадає крок `cd` у теку проєкту. Для клонування показуйте HTTPS, бо SSH працює лише в тих, хто налаштував ключ.

**Запуск.** Одна команда й опис того, що має з'явитися, щоб читач бачив, що все спрацювало.

**Конфігурація.** Назви змінних середовища й посилання на `.env.example`. Реальні значення секретів у README не пишуть ніколи.

**Структура проєкту.** Коротке дерево з поясненнями, що лежить у кожній теці.

**Як долучитися.** Посилання на правила гілок і комітів, на процес рецензування.

**Ліцензія.** Назва й посилання на файл LICENSE. Без ліцензії код формально не можна використовувати.
